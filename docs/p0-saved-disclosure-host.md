## Source preparation

`source_context` validates the existing raw-body ZIP, complete capture manifest,
counts, hashes, locations and run-bound clocks. Every required original packet body
must match its original PDF and all of its regenerated page-text identity. Missing,
empty, control-character-damaged, mismatched or oversized material is not silently
clipped or replaced. The original extractor/dependency pins are reused.

These are format/identity checks, NOT proof of semantic readability, source truth,
latest issuer completeness or research acceptance. The input question explicitly
means STATIC saved-announcement triage, not a current whole-company update. An
unreadable required body must remain an execution/source gap, never a completed
WAIT. The actual model/semantic review can still reject material that passes
mechanical checks. No OCR or source-site request is performed here.

Preparation records actual local saved-PDF read attempts, including failed ones,
in `preflight-read-events.json`. These are not source-site visits or a global tool
journal. Full original archives and actual run/artifact metadata stay in the same
host artifact, subject to its stated retention period.

Context, preflight and Discovery use the existing Retainer filenames. `prepare.json`
holds the original `DiscoveryInput`, not a self-authored admission PASS. The context
seed's internal publication time comes from its actual Git commit, not a backdated
filing timestamp. Original filing publication and retrieval times remain unchanged
inside the original packet. A short prospective cutoff is declared before the
Discovery write; its commit must precede that cutoff, and actual time must cross
the cutoff before input preparation. Missing that bound stops; it never invents a
past commit or truncates an event clock. The original `prepare_input` validates the
result before an immutable input is written.

Any prior auxiliary attempt record prevents automatic preparation. Partial context
or preflight files are not permission to resume. Failures use the existing
pre-execution-failure shape, retaining original packet identity, NOT_EXECUTED and
Funnel NOT_REACHED. Uncertain mutations stop without compensating writes or retry.

## Host and limits

The trusted host applies Human's project-dedicated Sub2API authorization to a fixed
public-disclosure/context shape, excluding Human/account/position/secret records.
A computed egress digest only binds bytes; it does not grant authority to itself.
Sources cannot choose a callable, endpoint, question policy or executable path.

There is **no additional daily provider money/call/company quota**. The six-company
scope here is the existing scan/adapter implementation coverage, not a Human
prohibition on useful broader research. Broader compatible inputs require reviewed
source/adaptation work, not another budget permission request.

The host follows the original finite saved scan (original MAX_PACKETS=10), serially.
Already-reserved keys never run again. Known local text/context gaps may be retained
while this declared FIFO pass advances; unknown, identity, clock, provider,
validation or uncertain-retention failure stops the batch. It never picks a more
convenient company to reclassify a failed attempt as successful.

Each independent work unit gets the ORIGINAL bounded GitHub client (180 GET/API
calls per client), without resetting any client within an attempt. Source loading
uses its own original client. Client counts are retained in the batch receipt;
native create-only Contents writes are separately in intake/Retainer receipts and
are not falsely included in GET accounting. Collector's original 180-call,
60-source and 128MiB publication limits remain unchanged. This composition is not a
new rate-limit framework or a bypass of a failed attempt's allowance.

Each prepared question uses the original maximum of one Pre and only necessary
Quick, no model tools or automatic Deep; the original SDK timeout, context/output
limits and zero retries remain. The host applies the original SIGALRM pattern at
15 minutes PER QUESTION, not one 150-minute allowance for an individual question.
The workflow's finite wall limit also bounds the complete pass. These are execution
safety limits, not daily financial quotas. Missing/damaged sources and no eligible
question must never be reported as all-market quiet.
