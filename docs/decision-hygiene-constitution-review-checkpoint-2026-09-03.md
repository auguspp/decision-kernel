## 4. YTO — Research can be complete before probability exists

The YTO dogfood reconstructed the causal chain as:

```text
parcel volume / share
→ unit revenue
→ unit cost
→ sustainable unit profit
→ franchise / network health
→ capital investment
→ OCF / FCF
→ ROIC
→ owner economics
```

The research could identify:

- observed unit economics;
- the role of price discipline and anti-involution policy;
- capex / cash-conversion questions;
- unresolved franchisee economics;
- aviation / international optionality that did not deserve Base credit;
- a coherent set of causal worlds;
- specific future observations that would resolve key uncertainty.

But the current PIT did not support a defensible full cardinal probability measure over those worlds.

The correct method result was:

```text
RESEARCH COMPLETE ENOUGH = YES
PROBABILITY = NOT ESTABLISHED
NUMERICAL ODDS = WITHHELD
```

The case therefore rejects the hidden equivalence:

```text
Research is complete
==
probabilities must exist
```

That equivalence is false in at least this economic species.

## 5. GigaDevice — probability readiness has degrees

GigaDevice produced a different result.

The research could support useful probability statements such as:

- some extreme downside / upside worlds are less plausible than central worlds;
- near-term scarcity and eventual normalization both have evidence;
- certain world orderings are more defensible than others;
- the total right tail should not dominate the state space.

What it could not support was a precise complete measure such as:

```text
10% / 20% / 30% / 30% / 10%
```

without more product-level duration, profit-sensitivity and terminal-model evidence.

Therefore:

```text
RESEARCH COMPLETE ENOUGH = YES
TAIL / ORDINAL PROBABILITY KNOWLEDGE = YES
CARDINAL PROBABILITY DISTRIBUTION = NOT ESTABLISHED
```

This is important because a binary architecture of:

```text
probability exists / probability does not exist
```

can itself throw away information.

At the same time, the case does **not** justify adding a `PARTIALLY_ESTABLISHED` enum.

The repeated method signal should first survive more real use.

## 6. Sanhua — one company can contain multiple probability maturities

Sanhua has a materially more stable core operating model than the first two live cases.

Its refrigeration and automotive businesses provide:

- long operating history;
- relatively stable segment margin structure;
- observable revenue and cash-flow base;
- a more stable industrial Reference Frame;
- a sell-side expectation envelope that can reasonably constrain the core earnings state space.

This makes the core more probability-friendly.

But the same company also contains liquid-cooling and humanoid-robot optionality for which public PIT evidence does **not** yet establish:

- standalone revenue scale;
- sustainable margin;
- customer allocation;
- capital intensity;
- incremental ROIC;
- durable owner earnings.

Therefore the epistemic structure is not simply:

```text
SANHUA probability = high confidence or low confidence
```

It is closer to:

```text
core probability structure = materially constrained
optionality probability structure = not established
```

A single five-world total-company distribution can conceal that difference.

This is a stronger architecture signal than merely saying optionality is uncertain.

It says:

> **Probability qualification may attach to different causal components at different maturity levels, while current total-company scenarios compress those differences into one normalized distribution.**

Again, this does not yet authorize an `Optionality` object, probability subgraph, or component state machine.

## 7. Xiamen Tungsten — the method improves failure attribution

The historical Xiamen Tungsten retrospective is valuable because it documented real analytical mistakes before any later stock outcome could rewrite the story.

The early research effectively used an incomplete Reference Frame:

> asset-rich industrial company + unusually high impairment + valuable future resources

while failing to make the tungsten-price regime the dominant upstream state variable.

That frame error then propagated:

```text
Reference Frame Failure
→ Inference Failure
→ premature Probability
→ Valuation / Timing Failure
```

Examples documented in the historical retrospective included:

- annualizing H1 profits generated in a high tungsten-price environment while implicitly normalizing to a lower long-run commodity regime;
- assigning exact scenario weights before the driver model was complete;
- pulling future mine / project mature economics too close to current value before ownership, capex, quota, timing and operating economics were resolved;
- treating an integrated upstream/downstream business too linearly as commodity price -> profit.

Decision Hygiene therefore did more than make the old research sound cautious.

It identified which layer failed.

That matters operationally because the corrective action differs by failure type:

```text
Evidence Failure
→ fix acquisition / source reliability

Classification Failure
→ fix claim admissibility / assertion scope

Reference Frame Failure
→ rebuild the model class and dependent underwriting

Inference Failure
→ rebuild causal transmission

Probability Failure
→ recalibrate only after worlds are structurally valid

Valuation Failure
→ repair value translation / horizon / capital treatment
```

This negative control supports the failure-attribution taxonomy in the method note.

It does not satisfy the stronger Human-decision / outcome negative-control requirement.

## 9. Repeated architecture pressure

The current Kernel requires a committed `ResearchSnapshot` to contain scenarios whose probabilities sum to approximately 1.

That requirement creates a useful deterministic contract once a cardinal probability distribution is genuinely part of the frozen Belief.

The dogfood shows a repeated pressure, however:

```text
Research may be causally mature enough to freeze
while
cardinal probability is not epistemically qualified.
```

Under the current shape, the Research process has three bad temptations:

1. keep researching indefinitely even when remaining uncertainty resolves mainly through future observation;
2. invent exact scenario weights merely to satisfy the Snapshot contract;
3. refuse to freeze a useful Research state because numerical Odds cannot yet be produced.

All three are undesirable.

The dogfood therefore supplies real evidence that:

> **The current `ResearchSnapshot` probability invariant is doing two jobs at once: freezing Research and certifying a cardinal distribution for deterministic Odds. Those jobs may need to become separable in a future Constitution revision.**

This is the central architecture pressure discovered by the experiment.

It is not yet a change request.

## 11. What is not ready to graduate

### 11.1 A probability-readiness enum

Do not add:

```text
NOT_ESTABLISHED
PARTIALLY_ESTABLISHED
ESTABLISHED
```

as a production enum yet.

Reason:

- the conceptual distinction is useful;
- the exact operational boundary is not stable enough;
- qualitative / ordinal probability knowledge may have more than one form;
- an enum may create checklist theatre before it creates invariants.

### 11.2 A separate Optionality object

Sanhua exposes a real core-versus-optionality epistemic asymmetry.

That does not prove the correct representation is a new `Optionality` entity.

It may ultimately be better represented through scenario structure, claim usage, valuation bases, or another simpler composition.

### 11.3 A new Research-complete state machine

Do not add another lifecycle merely to say that broad Research is done but Odds are not ready.

The method can already stop and record why.

The final software boundary should be chosen only if a mechanical invariant is repeatedly violated without it.

### 11.4 A new Human wake gate

Explicitly rejected.

`HumanResearchSurface.status + attention_eligible` remains the sole Human wake gate.

Probability readiness, if ever encoded, must not become a second competing Human attention gate.

### 11.5 A probability generator

No Bayesian network, Monte Carlo engine, LLM probability filler, or calibration layer is authorized.

The current problem is not insufficient numerical machinery.

It is qualification of whether numbers deserve to exist.

## 12. Preferred future Constitution direction — hypothesis only

If future evidence eventually crosses the Constitution threshold, the preferred direction to review is:

> **Decouple the ability to freeze decision-useful Research from the requirement to certify a complete cardinal probability measure, while keeping numerical Odds hard-dependent on a qualified cardinal distribution.**

Conceptually:

```text
causally complete / PIT-frozen Research
        ↓
may or may not have cardinal probability qualification
        ↓
if qualified
    → numerical expected-value / positive-probability Odds may run
if not qualified
    → valuation map / causal worlds / monitoring remain available
    → numerical Odds withheld
        ↓
Human Surface may still receive decision-useful Research attention
        ↓
Human decides
```

Important constraints on any future implementation:

1. `ResearchCommitPackage` must not become a truth judge or commit authority.
2. `ResearchSnapshot / commit_snapshot()` remains the place where Kernel identity, PIT, exact Evidence set and frozen semantics are protected unless a future Constitution review explicitly changes that invariant.
3. No placeholder probabilities merely to satisfy serialization.
4. No second Human wake gate.
5. Numerical Odds must never silently degrade from probability-weighted math into narrative scoring.
6. Valuation Map != numerical Odds.
7. Partial ordinal knowledge must not be silently rounded into a complete measure.
8. Price must not be used to back-solve Fundamental Belief merely to unlock Odds.
9. Existing committed snapshots remain immutable and auditable.
10. Existing live Odds policy must not be altered to compensate for Research uncertainty.

This is a design hypothesis, not an approved ADR.

## 13. Why not change Kernel now?

A Constitution change should require more than repeated discomfort with a schema.

The missing evidence is specifically **outcome-backed discrimination**.

We still need to know whether allowing Research to stop before cardinal probability actually improves later decision quality / attribution rather than simply making the process more comfortable.

A clean negative control should be able to answer questions such as:

- Did a forced probability distribution cause false conviction that materially affected a Human decision?
- Would a probability-withheld Research state have better preserved uncertainty?
- Did the missing cardinal measure hide genuine indecision, or correctly prevent false precision?
- Was later error primarily probability calibration, Reference Frame, valuation, Odds, or Human action?
- Would the proposed Constitution direction have changed the decision surface in a useful way?

Without a case containing a frozen Human judgment and later Outcome, those questions remain partially counterfactual.

That is exactly when a mature Kernel should resist architectural enthusiasm.

## 14. Constitution-change eligibility criteria

Reopen Constitution review only when at least one of the following evidence paths exists.

### Path A — strict historical negative control

A preserved case with:

```text
PIT Research
+ explicit Human Decision
+ Action / No Action
+ predefined or cleanly reconstructable evaluation horizon
+ later Outcome
+ post-outcome attribution
```

and enough lineage to assess whether forced probability materially degraded the decision.

### Path B — prospective controlled case

A future real decision case where, **before outcome**, the repository freezes both:

1. a Decision Hygiene research state that withholds unsupported cardinal probability; and
2. the closest current-Kernel cardinal counterfactual without allowing that counterfactual to drive the Human decision.

Later Outcome can then test which representation was more calibrated and decision-useful.

This is preferable to reconstructing a counterfactual after the fact.

### Path C — repeated operational corruption

Multiple future Research cases demonstrate that the current required-probability invariant causes one of these observable failures:

- invented probabilities are repeatedly inserted only to permit commit;
- useful Research cannot be frozen without violating method integrity;
- downstream Odds are repeatedly produced from probability measures that reviewers explicitly judge unqualified;
- immutable lineage becomes harder to preserve because researchers delay freeze until fake numerical completeness is available.

Even then, the smallest architecture change should be preferred.

## 15. Next validation protocol

Until the threshold is crossed, future Full Research should dogfood the method without schema changes.

For each serious case:

1. declare the Reference Frame;
2. identify 3–5 decision-critical variables;
3. construct causally coherent worlds before probability;
4. explicitly state what probability knowledge is actually supported:
   - none;
   - tail exclusions;
   - ordinal ranking;
   - interval / bound knowledge;
   - full cardinal measure;
5. do **not** force exact weights if unsupported;
6. if a production `ResearchSnapshot` still requires exact weights, clearly distinguish the production counterfactual from the Decision Hygiene conclusion;
7. preserve both without rewriting prior frozen state;
8. run numerical Odds only from the production path when its required inputs are intentionally accepted as qualified for that path;
9. keep `Investment Authority = NONE`;
10. record later Human Decision / Action / Outcome prospectively whenever a real case reaches those stages.

The most important addition is #10.

The repository now has enough Research artifacts.

What it lacks for the next Constitution decision is **longitudinal decision evidence**.

## 16. Learning-system implication

The missing negative control reveals a broader product lesson.

Decision Kernel has become strong at preserving:

- Research lineage;
- evidence identity;
- deterministic calculations;
- Human review boundaries.

But the historical repository is comparatively weak at completing:

```text
Research
→ Human Decision
→ Action / No Action
→ Outcome
→ Attribution
→ Learn
```

This does not justify building a new outcome subsystem now; the old repository already contained generic Outcome domain concepts.

The immediate need is behavioral and operational:

> **When a real Human investment decision occurs, freeze it and later close the loop.**

Without that loop, method debates can become permanently pre-outcome and self-confirming.

The correct response is better longitudinal evidence, not more schema.
