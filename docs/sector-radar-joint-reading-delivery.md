## Pipeline and failure behavior

The existing producer runs first, followed by its mandatory offline replay and existing context renderer. `.github/scripts/build-sector-radar-reading.py` then composes the unchanged joint-reading CLI. It receives no market credential and performs no network request. The workflow installs the existing `discovery` extra for the already-used review verifier; no new dependency is declared.

The wrapper binds the replay receipt, sealed audit identity, actual state/output bytes, exact parent hints and saved context to this repository/workflow/run/attempt/commit. After rendering, it checks the same bytes again. Market calculations, original operations, candidate ledger and sealed input audit are not rewritten. Economic input cutoff is the actual later reading time, not the market session or signal time; this does not inject later company evidence into the original signal.

Keep the existing all-or-nothing publication convention: joint generation failure prevents subsequent authoritative state-artifact and cache upload. Failed-run audit upload and truthful summary still run. There is no `continue-on-error`, old-page fallback or new successful read-only dispatch that could confuse the previous-success state locator. A local calculated state can exist after failure but must not become the next remote authority. The same workflow serialization, restoration semantics and no-gap rule remain in force.

This intentionally adds a delivery prerequisite. A corrupt source mapping is an operational failure, not a new market signal. Fix the precise input before a fresh same-session dispatch; if the next available completed session has passed an unpersisted day, use the separate qualified recovery procedure, never skip the gap. Removing this prerequisite later would require an explicit operations design rather than silently swallowing failure.

## What is retained

The joint folder contains the existing four page/data files plus `README.txt`, `inputs.zip` and `delivery.json`. The source ZIP freezes exactly the supplied seed, complete accepted-review directory (including empty directory identity), industry mapping, parent hints, company mapping, selected company Evidence containers and a read-only copy of the already verified market bundle. It is assembled before rendering and all originals are rechecked before final publication.

Use standard-library ZIP, not a new archive or storage service. Empty accepted directories and `.gitkeep` are inside the nested ZIP, so the outer Actions upload need not enable hidden-file collection. Both currently empty registry and explicitly supplied nonempty registries are subject to the existing input resolver; pending drafts are never accepted automatically. Aggregate delivery limits are 64 MiB and 2048 files/directories, fail without truncating sources. Existing source-parser and review budgets still apply independently.

Rendering occurs outside all source roots. Final transfer is staged on the destination filesystem, byte-checked and renamed; it does not assume RUNNER_TEMP shares a filesystem with the workspace. Prior pages are never overwritten, and failed owned staging is removed.

`delivery.json` records exact input/output hashes, original market/ledger/association identities, actual build commit, reading cutoff and generation time. It is not a signature, Human reading record, certified Git membership of every declared historical source, original-PDF revalidation, remote upload receipt or recovery source. Company Evidence stays EXTRACTED_VALUES/PARTIAL. Neither a quoted PDF hash nor a financial-role label upgrades source truth or promises permanent raw-document retention.

## Replay and retention

Artifact retention remains 90 days. The embedded README gives an exact invocation of the existing company CLI against the unzipped copied inputs and original reading cutoff, using the matching code commit. New generation time changes display bytes, not the fixed-input projections. Verify the GitHub run and outer artifact digest as well as the local manifests before trusting a package.

The ZIP is a reading-input copy only; do not use it as a new production restore source. It does not archive every historical state, producer response or company PDF. After expiry, replay needs an externally preserved complete artifact or equivalent exact originals; hashes alone cannot recover data, and refetching a URL may produce a different version.
