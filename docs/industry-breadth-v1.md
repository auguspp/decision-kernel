# Industry breadth: broad observation, selective explanation

Human scope correction: #297/5772994231. Reuse and exact original-source audit:
#297/5773065934. This is the next P1-4 slice, not full P1 acceptance.

LC/CU/RB are retained detailed regression samples, not the discovery universe.
The existing HiThink no-parameter main-continuous basis endpoint supplies a broad
snapshot in one request. Its retained September20 sample already has144rows and
83distinct source codes, including4financial-index series and multiple spot
quotations. Those counts describe this specific response, not a fixed future
universe or83independent economic signals.

`industry_breadth.normalize` retains every returned row or explicit unidentified
row, original thscode/ticker/spot-ID/reference-site, alternative/default marks,
source dates, numeric gaps and byte/representation identity. It never chooses a
preferred quotation, derives an investment rank, assumes uniform units/percent,
turns a snapshot into history or establishes completed-session finality. Capture
time does not become source publication time. Future/missing row dates remain
gaps; source-level future clocks are rejected. Financial-index rows are separate
market context, not industry fundamentals. A second capture of identical content
does not itself create a new content version.

The official illustrative basis sign/rate and some original response rows differ.
Therefore this breadth view deliberately keeps raw rates without percent suffixes
or cross-commodity comparisons. Existing reviewed LC/CU/RB history calculations
remain unchanged. Any later comparison needs compatible spot, contract, units,
periods and actual source history; do not loosen the three original contracts.

## Native daily source

`radar-industry-breadth` follows the existing owned first-attempt main Sector
workflow completion, independently of Sector success or price strength. An
explicit native manual entry also exists. It checks independent main CI for the
actual checkout. Exactly one fixed provider request at most; no per-code fan-out,
retry, new cron, external scheduler migration or model call. Missing credentials
produce an explicit unavailable attempt without a request. Existing requests
Session/no-env/no-proxy/no-redirect/streaming policies are reused. Body4MiB,
rows2048, job5minutes. Non-200 error bodies are not archived; safe HTTP status and
error type are retained. Credential reflection/malformed unsafe JSON is discarded.

Only the source step receives the existing HiThink key; it gets no GitHub write
or model credentials. Source text supplies neither paths nor execution authority.
Safe original body, request and receipt are create-only. Replaying them binds
native run/head/event/attempt/clocks and verifies the raw digest, without executing
saved code. A completed finite attempt can still contain an unavailable source.

## Same-reading delivery

The original publisher opts in with `--include-industry-breadth` after existing
external sample reading. It reuses the already-verified historical archive/cache
with no extra historical GET and separately examines the newest native invocation.
Native absence/failure/expiry/rejection never falls back to the old sample. Both
sections expose original dates and statuses in `details/radar/industry-breadth.*`.
The36-hour capture-age label is not source freshness or trading-day qualification.
Normal output/file/API budgets remain unchanged. Other Radar/Research/Watch lanes,
old source bytes and old detailed series remain unchanged.

Noncommodity industry coverage is still incomplete: semiconductor prices/inventory,
vehicle sales/activity and underlying shipping rates are not supplied simply by
reading a futures snapshot. An EC futures row is not an underlying freight-price
observation. Expand compatible low-cost observation before a company question
exists; spend deeper source/Research effort only on useful economic questions.
There is no requirement to manufacture more Research or alerts after widening
coverage. Data != Evidence != Judgment != Decision.
