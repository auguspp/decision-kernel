## 1. 项目是什么

Decision Kernel 不是交易系统，也不是自动选股器。

它的产品目标是：

```text
现实世界
  ↓
Radar / Attention Allocation
  ↓
Research
  ↓
冻结 ResearchSnapshot / Belief
  ↓
Observed Market
  ↓
Odds
  ↓
Decision Rehearsal
  ↓
Human Surface / Decision Inbox
  ↓
Human 最终决定
```

用户最终体验应该接近：

```text
打开 Decision Kernel
→ 今天有值得我看的东西吗？
→ 有：看少数几个
→ 没有：关掉
```

不是：

```text
打开 GitHub Actions
→ 读 runner / SHA / JSON / PIT error / provider log
```

### 当前产品定位

**attention allocation + decision rehearsal**，不是 stock picker / auto trading。

理想效果：

```text
100 个股票 / 新闻 / 报告
→ Radar / Research / Kernel
→ 97 个 quiet
→ 3 个值得 Human 看
```

## 2. 不可破坏的 Authority 边界

必须一直保持：

- `Research != Recommendation`
- `Odds != Recommendation`
- `DecisionRehearsal != Investment Decision`
- `Human Surface != Human Decision`
- `investment_authority = NONE`
- Human 是最终 Investment Decision Owner
- Autonomous Research != autonomous investment decision
- ResearchSnapshot COMMITTED != Human approval

### Human wake gate

唯一 canonical wake gate：

`HumanResearchSurface.status + attention_eligible`

- `DECISION_WORTHY_REVIEW` + `true` → wake Human
- `NOT_ELIGIBLE_INSUFFICIENT_ODDS` + `false` → quiet
- `DecisionRehearsal.human_status == HUMAN_DECISION_REQUIRED` **不是** wake gate
- `INSUFFICIENT_ODDS` 默认 quiet

不要在 UI / Radar / CLI 再造第二套 “worth attention” 判断。

## 4. Constitution vs Research Method

不要把旧 Decision OS 的完整研究 recipe 冻进 Kernel Constitution。

### Kernel invariants

只有缺失后会让 PIT / Belief / Odds / exact lineage / Human accountability 失效的东西，才考虑进 Kernel。

例如：

- PIT no future leak
- scenario probability distribution 完整
- exact evidence lineage
- information identity / hashes
- Human accountability

### Research Contract / Method v1

属于可替换研究方法：

- variant perception
- market expectation map
- normalized earnings
- valuation framework
- fundamental / expectation / liquidity clocks
- monitoring indicators
- scenario drivers
- valuation stress

Hard test：

> 一个字段删掉后，PIT / Belief / Odds / exact lineage / Human accountability 是否变得无效？
>
> Yes → maybe Kernel；No → method / quality / presentation。

`Kernel Research semantics ≠ Research Method policy`。

## 10. Radar：真正难的 part

用户自述注意力长期偏科技硬件，因此容易错过农业、煤炭、CRO 等阶段性变化。

Radar 的价值不是“AI 选今天最该买什么”，而是：

> **现实里哪里正在发生变化，值得把研究注意力挪过去？**

### Radar 最好分两层

```text
Sector / Theme Radar
→ 哪里发生值得注意的变化？
↓
Company Discovery
→ 在这个领域哪些公司最值得表达 / 研究？
```

Radar 是 **Attention Allocation**，不是 Investment Decision。

### 用户已有 Web Radar 沉淀

用户已经有 Web 侧：

- 产业拐点扫描
- 每日研究分配
- Radar Attribution Review

这套沉淀里有很多成熟方法：

- A/H 全行业 / economic-node 广覆盖
- 不是只按一级行业，而是细分经济节点
- 行业状态：未确认 → 早期形成 → 已确认 → 弱化 → 失效
- company-led 不能直接升级为 industry
- 基本面 / 市场认知 / 资金迁移分开
- 7–14 天 PIT 回扫与漏检审计
- 找 2–5 个真实经济暴露的 A/H 表达标的
- Daily allocation: DEEPEN_NOW / WAIT_FOR_TRIGGER / DROP_FOR_NOW
- Attribution: Discovery Failure / Leadership Failure / Mapping Failure / Correct Rejection

这些是**用户方法论沉淀**，但不能完全信任；需要和新 repo / fresh prior art / natural runtime 互相验证。

### 旧 Decision OS Radar 也有金子

旧 repo 里曾有：

- `radar.py`
- `market_radar_attention.py`
- `market_slow_radar.py`
- `radar_research_adapter.py`
- `radar_economic_nodes.json`

值得保留的语义：

- SECURITY / SEGMENT / ECONOMIC_NODE
- industry state machine
- price path 不能单独升级 Fundamental
- 需要独立 industry / multi-company / supply-chain corroboration
- why_now
- next_discriminating_search
- stop_or_downgrade_condition
- research allocation only

旧实现的问题：

- industry breadth 当时只有 4 个 nodes，明确 `NOT_ESTABLISHED`
- provider / fetch / cache / receipt / ledger / orchestration 太重
- 不要整体搬回新 repo

## 14. What NOT to do

1. 不要为了 Radar 做新的 Kernel domain。
2. 不要让 price / breadth / change-point 单独升级 Fundamental belief。
