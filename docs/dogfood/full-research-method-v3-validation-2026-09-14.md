## 3. 三份历史材料的具体对照

### 兴业科技 002674.SZ：结构性遗漏，而不是只漏一个情景

读取：`docs/readings/002674-xingye-full-research-revision-2026-09-14.md`，blob `454fcdc441bc060e106dbec6ecf9f961ae0258dc`，M 如上。

原记录第1节明确记载首版采用“可修复皮革 + InP期权”和同方向世界，Human 挑战后才纳入旧业务价值衰减、新业务接管经济贡献的世界。第2–3节也明确：没有建立收入持续崩塌，而是经济回报恶化。两者不能在方法摘要中混为一谈。

v3 的对应动作：先列经济引擎与资本关系；区分收入、经济利润和现金方向；允许业务表现分化，但核验共同融资约束；新业务商业化与股东资本回报分别论证。

未来复测的验收问题：在 Human 提醒之前，是否主动识别这种结构及其关键现金/资本问题？仅写了‘主业+新业务’两个栏目，或者沿用一张对角线估值表，不算完成。

**本次没有重算其已保存的 provisional first-entry，没有把用户接受升级为模型正确，也没有给原报告新增合格认证。**

### 恒瑞医药 600276.SH：兑现路径和重复计价

读取：`docs/readings/hengrui-600276-research-odds-2026-09-11/round3/research_supplement.md`，blob `7927a8f0082c25ea48caa57f05b6302176fe3fdd`。

该修订底稿区分许可签约/确认/收款与完整研发履约成本，检查经营现金、资本化开发、利息与其他股权价值的范围，并保留仍不能确定的正常化现金。它支持把“收入到股东现金”作为复测能力，不支持编造本轮新的现金预测。

v3 的对应动作：同期间利润—现金—资本桥；费用化/资本化研发不重扣或漏扣；现金本金、金融收益、首付款和权益价值不得重复；取得说明会问答失败不能叫公开证据穷尽。

未来复测的验收问题：是否主动发现现金转换与范围问题，而不是 Human 追问后才补？能否明确哪些经营结论已经支持、哪些现金仍无法可靠约束？

### 光电股份 600184.SH：单位对了仍不代表模型成立

读取：`docs/readings/600184-research-method-review-2026-09-13.md`，blob `174e02ecc48eb851324b830798f996c0f6705a02`。

该记录确认亿元/bn 的10倍单位标签错误，撤回历史高低点作为价值地板或唯一市场信念的推断，并说明跨机构/跨目标年预测不可直接称连续下修。原条件算术与经营/估值合理性是两项检验。

v3 的对应动作：单位与公式真实复算；独立估值依据；预期样本可比性；不为得到可参与价格而移动世界；完整下行与条件回报共同展示。

未来复测的验收问题：是否在首版交付前区分算术正确、估值桥支持与 Human 风险偏好，而不是修正单位后宣称方法通过？

## 4. 实际执行的合成算术检查

全部输入为合成单位，与任何股票无关；假定同期间、无少数股东、无其他利息税项分类差异。Python Decimal 执行了8项断言：

| 检查 | 输入与结果 | 防止的错误 |
| --- | --- | --- |
| 1. CFO | 净利润100 + 非现金费用20 - 营运资金增加30 = 90 | 忘记现金转换 |
| 2. 两条现金路径一致 | 90 - capex40 = 100 + 20 - 30 - 40 = 50 | CFO之后又扣一次营运资金 |
| 3. 融资前现金 | 50 | 把错误二扣后的20当正确结果 |
| 4. 加净借款 | 50 + 20 = 70 | 将70全部称为业务创造的自由现金 |
| 5. 引擎勾稽初态 | 旧业务100 + 新业务(-30) - 总部10 = 60 | 忽略集团成本 |
| 6. 引擎反向变化 | 旧业务70 + 新业务20 - 总部10 = 80 | 强迫两个引擎同向变化 |
| 7. 单位 | 1亿元 = 0.1 bn CNY | 亿元/bn错位 |
| 8. 每股结果 | 利润从100至120、股本从100至150，每股从1至0.8 | 利润增长自动等于股东每股增长 |

这些只检验这里的算术，不证明真实报表分类、未来经济假设、未知资本归因或研究员识别能力。

## 5. 下一阶段能力验收：用正常研究请求取得未提示样本

本次不额外挑公司或消耗 API 开新 Research。将接下来正常获准的 Full Research 中、未被用于本轮修法的不同经济类型作为首批 prospective 样本；例如单引擎成熟业务、周期/重资本业务以及不同于本次转型的公司。首批可以用3个案例检查流程可用性，但3例不足以证明总体可靠性。

对每例先冻结 cutoff、可用证据、模型/工具/方法版本、数据访问和实际成本范围。保存第一版交付，不能先让 Human 指出主矛盾再称首版主动识别。凡已读旧答案、修订报告或后续结果的试验都标为 exposed regression，另留真正未用于修法的样本。

比较旧方法与v3时，应保持证据范围、任务、工具条件和成本限制可比；有差异必须披露。不同方法必要的阅读开销也计入成本。不能只比较v3多轮精修与旧法的一次草稿。若获准重复试验，保留全部尝试，不挑最好的一次，也不重跑直到通过。

审阅以具体底稿为依据，按维度写通过/部分/失败/未观察及理由，不以关键字匹配、报告长度、与既有目标价接近或模型总分验收。复核者尽可能不知道版本标签，记录实际信息暴露；模型评分只能辅助，重大判断需人工抽查。[外部方法校核见v3正文E4–E5。]

观察至少覆盖：

- Human 提醒前是否发现重大经济结构与关键问题；可发现遗漏的严重度及依据。
- 因果/竞争/周期结论是否有材料支撑，参照类是否有资格，有无伪精确概率。
- 现金、资本、权益范围和每股结果是否可复算，有无重大重复计价。
- Challenger 是否带来有证据的修正，是否也产生错误挑战、无必要阻断或迎合。
- 正文是否能回答当前问题，哪些 UNKNOWN 应止步，以及真实时间、查询/API成本和 Human 负担。

低遗漏但一律 NOT METHOD-READY、没有新信息却无限搜索、或者到处拆分/制造 Frame，同样可能是退步。阶段验收不要求每家都能买，不要求概率全部建立，不以买点数量或短期涨幅评分。

若仍出现重大可发现遗漏，先分清 METHOD/EXECUTION/SOURCE/JUDGMENT 的混合根因；只有反复出现的新共性方法缺口才修正文档。是否需要独立复核调用、自动底稿提取或其他工程，另交 Requirements Management 排期，不能由本页直接开启。
