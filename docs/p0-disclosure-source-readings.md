## Preserve the original; label the readable representation

`source_context()` still replays the original pypdf extraction and requires the
same PDF hash, original text hash, page count and every original page value.
Original encrypted/corrupt/size/page/text-limit rejection is not caught and
bypassed by the new parser. Its default, non-opted-in behavior stays strict.

The trusted preparation opts into one PDFium pass only when that exact original
representation has missing or damaged page text. Every page of the same PDF is
kept; line endings may normalize, but controls, missing pages and truncated text
are not silently deleted. PDFium version/method, original PDF/text identity,
per-page text/method and the complete representation hash are retained under
`source.json -> source_capture.page_readings`. The original disclosure packet
remains intact alongside it. The admitted context seed and original egress hash
cover both. This is one original source, never two independent Evidence votes.

Readable text is not a guarantee of table-column alignment, accounting meaning
or true company statements. Those uncertainties remain explicit. A font decoder
is not a semantic validator and no numeric values are invented here.

## Scanned pages require an actual reading, not a blank-page exception

If PDFium cannot provide qualified text for a page, preparation renders that
whole page at fixed 2x scale, no crop/extra rotation, RGB, with annotations. Raw
pixel identity excludes encoder metadata and row padding. Page count is capped
at 200, extracted text at 1,000,000 characters, and render allocation at
16,000,000 pixels. The existing 16MiB PDF and workflow runtime limits remain.

A reviewed main file at
`research_runs/source-readings/<pdf-sha256>/page-<number>.json` can supply an
**AI_VISUAL_READING**, only when the PDF, page, engine, full-page render pixels,
reading scope and explicit unknowns match. Review text is untrusted source
interpretation, never an instruction or Human research continuation. A matching
hash cannot prove an AI actually read something; the interaction/review process
owns that fact. The code only validates bindings and clocks.

Only the exact current code commit is consulted, never a path/URL supplied by
the PDF. Review time must precede its main commit and the current check. Missing
reviews fail closed; changed, oversized, foreign or future records are not used.
The host reads the same main note again before approving the public egress hash
and before #337 can reserve a launch. Partial diagnosis, including render hashes,
is kept in the existing run artifact as `source-reading-events.json`.

The committed 1225555804 page-6 record is an actual whole-page AI visual reading
of the saved PDF's signature page, with signatory authenticity/legal effect and
handwritten date explicitly unverified. It is not an OCR transcript, Human
permission, signature authentication or a new company-economic conclusion.
Another unseen scanned page still requires its own genuine review; this does
not pretend to provide unattended visual understanding of every future PDF.

## Finite context size, no artificial daily quota

The actual saved CATL packet is 60,504 UTF-8 bytes; a readable nine-page
representation adds 13,947 bytes. Preserving both cannot fit the old 64KiB
request allowance. The existing pre-SDK byte ceiling is now **128KiB**, including
system text, full serialized input and generated output schema. Source context
still leaves the original 16,000-byte headroom; neither stage silently clips.
Observed local complete-context sizes were 76,140 bytes for CATL and 36,792 for
GigaDevice (local reference identities, not committed Research inputs).

This is a finite per-request technical limit, not a daily call/company/spending
quota. Original output-token, retry, stage/timeout, source/egress and legacy Suken
object/launch guards remain. Increasing a byte ceiling does not authorize an old
attempt to run again. Existing Human project resource authorization remains.
