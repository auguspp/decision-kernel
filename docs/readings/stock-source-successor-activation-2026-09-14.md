## Exact scope

Only `603353.SH` and `300711.SZ` may use the fixed `source-successor-v1/` child.
The successor binds all of the following before reserving a child:

- the original first-business parent selection/failure;
- the already-consumed `source-recovery-v1` selection/failure;
- Human permission #297 comment `5652950925` through the existing trusted
  source-preparation request;
- source-only run `34765190284` and exact artifact `10320565453` including its
  size/digest/head identity;
- the execution-time current fixed reading and its shown Stock history;
- the original saved source inventory/material identities.

A changed date, price, code version, permission number or representation hash
cannot create another successor. Any retained file under the fixed successor
prefix blocks another execution through the original create-only Retainer.

## Saved material and current inventory

The exact source-only ZIP is downloaded and validated by the existing bounded
archive reader. Old selected PDFs are consumed byte-for-byte from that artifact;
they are not fetched again and are not summarized. The original Guangha
`636462`-byte context identity remains explicitly bound in the request.

At successor execution time the existing CNINFO adapter performs one fresh,
coherent inventory query. The latest full report identity must remain the same
and every saved selected announcement must still be present. Any newly selected
announcement is fetched through the original bounded PDF transport and included
in full. A changed report or missing saved announcement fails closed instead of
silently converting the old source set into a new baseline.

Saved visual-page references are never silently rewritten. The same saved PDFs
are represented again through the current-main reading loader; current notes
must have the exact approved Git blob and the original engine/render binding.
This is an explicit source-reference upgrade, not new independent Evidence or
signature/legal authentication.

## Original host / Funnel

The existing `stock_research_host.run_item()` remains the executor. The new
native dispatch flag selects only the successor items, forces the already-merged
full-input path and supplies a saved-artifact capture adapter. Original
Retainer, admission, Pre, conditional Quick, SDK request construction, output
validation and Funnel remain authoritative.

Before launch the complete plain context is losslessly stored and decoded under
the existing full-input contract, and the exact Pre HTTP request is built with
the pinned SDK and a deny-network transport. Permission, fixed reading,
predecessors, current-main visual notes, stored bytes, decoded bytes and packet
identity are rechecked before each model stage. Quick is constructed and sent
only if the validated Pre route requests it.

Default first-baseline, old recovery and source-only modes are unchanged. The
workflow exposes `source-successor` only on explicit native dispatch and keeps it
mutually exclusive with `recover-sources`/`prepare-sources`.

## Authority / acceptance boundary

A green code CI proves only the adapter contract. It is not company Research,
provider/token-window acceptance, semantic acceptance, Deep, Odds, Action,
trade, position or monitoring authority. Production acceptance still requires:

1. fixed-head PR CI and review;
2. independent main CI and ordinary fixed-reading publication;
3. one explicit native successor dispatch in an Actions-capable environment;
4. artifact/model/work-result byte inspection;
5. ordinary fixed-reading publication of the resulting Stock work and direct
   readback.

Pre may STOP or WAIT under the original validator. Quick exists only after the
original Pre transition. Technical/source failures remain gaps and are not
converted into WAIT.
