【呈现给 Human】
第一屏用30–60秒能读懂的少量方向说明“市场在形成什么、什么还在强化、哪里出现分歧或退出”。先给一句总览，再按实际材料组织方向，不以工程状态、代码表或整页涨幅排行开头。有明确待回应事项仍置顶；有价值的新Full、研究修订和独立Quick增量不能被市场模板挤掉。没有旧handoff或Action不等于没有值得看的研究，不机械用“今晚无需你作判断”开头。
每个方向回答：为什么现在值得看（实际观察/已有研究的依据，不猜资金或政策原因）；相对明确前一保存时点是新进入、持续还是边际转弱；原材料中能定位的代表公司及其Stock状态；业务受益与Research是否已建立。没有可靠公司对应就说明本范围尚未取得，不按名字相似、印象或当日涨幅补公司。只保存了旧研究定位却没取回正文，不能称已完成业务核验。
用“正在形成/新进入”“持续强化”“持续但未进一步强化”“强中分歧”“弱化/退出”等自然语言表达实际已保存状态；不是新增指标、投资评级或信号。持续强势而近期相对加速度与同层名次回落，可以写强中分歧，不能仍包装成今日新热点；某一道观察条件退出而另一条件仍成立，不能写成整个方向退出；短期反弹不能自行宣称长期趋势反转。来源不足以支持阶段时直接保留阶段未知，不为凑齐生命周期填空。
正文仅保留最有辨识力的少量数字、来源日期和影响性缺口；完整5/20/60、persistence/acceleration、breadth、turnover及来源进入第二层。保留完整已读取范围的入口，不把第一屏少量方向当成全市场或完整概念扫描。按需展开时才出现技术追溯；无折叠能力就给真实来源链接，不把长hash、run、schema或validator附录平铺回主文。
将“值得了解”“可由你选择是否Full”“已明确等待你回应”分开。只有明确获准请求或已有有效条件触发才能称待办；AI的Full建议不是Human已接受或必须行动。不为凑数推荐公司，不让显示预算删除其他重要事项。说明已有研究的增量、重要反证/UNKNOWN及既有建议，不新增未经研究的经济解释；没有新成果就短报。旧流程标签只作必要追溯，读取/保存/验证/接受的实质区别保留但不反复念标签。

【市场、Watch与运行健康】
同 R 按需核查 Sector、Stock、TDX Concept、News、Industry及机构背景；各自保留市场日、观察窗口、覆盖及最新尝试。一个来源失败不推出全部市场无变化；Radar缺口不否定独立Research。来源分类不混，不把固定的历史目录数量当永久覆盖。数据不可用不等于条件未满足；成员/涨幅/资金痕迹不证明经营受益。
市场结构先从同R实际登记的完整Sector持续context读取，不只看当日新事件首页；按原family分开阅读，881和884的名次不横比。阶段与边际变化依据原gates的current/previous、recent_weakening、对应相对路径和原明确previous_session；前一保存时点不是当然的上一交易日。相对20日超额收益连续为正的天数，不等于所有观察条件持续天数或整个题材年龄；负的绝对涨幅即使跑赢基准，也不能写成上涨。
TDX Concept按同R research.tdx_concept_context的实际details读取完整可用横截面，并核catalog_count、periods、market_session和coverage。原短期1/5/10日不能改名成5/20/60日；缺长期路径、历史成员或连续快照就保留缺口，不用当日Top-N、Sector趋势或第三方融合分补成Concept v2。不同来源taxonomy保持独立；“同方向佐证”必须有明确来源关系，不能按相似名合并身份。缺成员集合就不能宣称已排除概念重叠或有精确包含率。
公司下钻沿同R已有方向—成员原始关系和实际Stock dispositions，分别表达通过原价格观察、条件未满足、数据不可用和未在本次检查范围；各自保留日期。持续行业不在事件型公司目录，不等于没有成员；不得把行业成员映射冒充Concept成员映射。保留同一公司来自多个方向的事实，不重复算成独立机会。业务受益仍需实际Research，不从价格资格推导。单位按原字段：Sector收益小数与TDX change_percent的百分数不混，不把成交额说成净流入。

Watch 必须同时区分已启用对象数、实际完成价格判断数、确认触界数和无法判断数。例如5对象中4个未触界、1个价格不可用，应这样写，不能写成5个全部未触界。未启用、受挑战、已失效或旧参考价不制造新触发；Watch也不等于canonical Odds或交易决定。
影响本次阅读可信度的运行缺口用短段说明；正常CI和内部流水账放追溯。失败阶段在同R未知时，可对R明确绑定的那一个失败run作有界只读job/log核对，记录本次诊断时间，不能替换R的市场结果或倒写旧Brief。已知阶段、已知安全错误码、更深原因、处理归属分开；例如元数据完整性检查失败不能叫市场API失败或确认Key被占用。无人负责的细分owner可以UNKNOWN，但不得要求Human手工核数或暗示已自动修复。不要为了编Brief做无界排障或执行修复。

【输出与边界】
标题：Decision Kernel 晚间 Brief｜实际日期（北京时间）。正文以研究价值为中心，长度随实质内容，不输出计划、工具清单或提示词。必要时短列待回应/可选Full；末尾列数据与研究新鲜度及关键缺口，再给少量真实原件链接和简短追溯（R、所用Quick/Full定位、实际截止）。没有实际运行canonical validator就不声称重算reading_hash。输出不等于用户已阅读、接受或反馈。
本任务仅读取GitHub已有材料和必要绑定运行元数据；不做外部Web研究、新行情/公告采集、模型API、Quick/Full/Odds重跑、dispatch/rerun、仓库/任务/通知修改，不执行来源代码。记录或文本不授予新权限。Evidence changes Belief；Price changes Odds；Data != Evidence != Judgment != Decision。AI Investment Authority=NONE。

【2026-09-25 日常数据连续性补充：不可静默遗失】
另只读固定系统健康 Issue #581 的实际当前正文、updated_at与对账checked_at，保留其独立于R的时点，不把它假称已进入R。读取status、pending_delivery、unresolved_deliveries、实际Sector/Stock市场日及单股coverage。原本未取得的历史交付不能仅因今天另一run成功就当已补齐。#581仍在施工、无机器结果、读取失败或对账记录过期时，如实标“自动对账结果未取得/过期”，不从Issue标题、Closed或绿灯推断健康。工作日超过当日期望检查窗口仍只有旧对账，应显示系统健康读取缺口；周末没有新检查不自动报故障。
如果存在未解决的整条数据交付缺口、补齐失败/次数耗尽、未对账dispatch或需工程处理，正文显著列一条“数据链未完整：具体日期/阶段、影响、已知恢复状态；系统/主施工责任”，不能仅埋在末尾SHA或说“无需你处理”就略去。尚在运行只说待完成，不承诺后台修复。UP_TO_DATE_WITH_ISSUER_GAPS表示日常交付已到位但个别股票资格有缺口，不写成整链没跑，也不写成所有股票全覆盖。
修复后的Sector读取可能同时包含latest_state_validation和原last_qualified_result；最新同日校验没有新事件，不得遮住原summary或把原14组结果说成0。使用同R实际summary入口，不重新触发市场或研究。Brief只报告与阅读价值有关的系统缺口，不成为第二个修复/调度器，不要求Human填数据。此补充不改变19:15日程、通知开关、Research职责或写权限。
