## Qualification and retention

Read at most20 main invocations of the exact concept workflow. Use the newest
attempt; do not search for an older success after a failed/active/expired/rejected
latest attempt. Run/main/attempt1/event/repository/code/clocks must agree. The
original Collector checks the archive digest, length, file paths and run binding.
The concept verifier operates on a bounded flat payload in a temporary directory,
not the working tree. It checks unchanged implementation fingerprints and actually
replays the original requests/bodies, then reconstructs JSON and HTML. Its result
must exactly equal the original CLI verification receipt.

Qualified COMPLETE and PARTIAL captures can be read. A PARTIAL source keeps its
member observations and explicit history/member gaps; the composed reading says
READ_OK_WITH_SOURCE_GAPS. Deliberately deferred details are not failed data or
zero activity. A failed capture contributes no fake empty successful source.

The exact ZIP, all original payload files, original verification and run metadata
are retained under the same pinned Git reading. Existing180+72 API and128MiB
bounds remain. Preflight includes the worst-case34 payload files, archive,
verification/run and three composition files. A concept-only failure rolls back
only its new files/cache, NOT already-retained institutional inputs, original
Sector/Research context or spent API calls. Composition/render/output failures
also fall back once to the other saved sources with an explicit concept gap.
This is not a retry of acquisition. Git history is read retention, not production
restore authority, an eternal backup promise or admission after artifact expiry.
