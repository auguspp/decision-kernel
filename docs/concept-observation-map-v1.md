## What changes for the reader

Known nonempty current member sets are organized by exact set inclusion.
Maximal observed sets are navigation representatives, not independent economic
clusters. Equal sets use an exact-code tie-break, but all indices keep their
own histories. Partial overlap is not collapsed. No transitive overlap closure
is taken. A detail contained by two distinct maxima appears under both and names
its other container; no invented partition. Missing membership remains unknown,
not an empty set that could be incorrectly classified as everyone's subset.
Individual member and source observation clocks remain visible in the JSON;
one capture is not an atomic simultaneous membership snapshot.

Every acquired5/20/60-day path remains available, regardless of its daily return.
No new acceleration/weakening gate or economically named stage is created.
The original persistence and left-censor flag remain; this is not the true trend
start. Unacquired histories are explicitly unavailable. A snapshot does not create
multiday history, breadth, company role, business exposure or a research result.

The whole unexamined universe is ordered by exact code, not daily performance.
A pure three-item `page`/`pages` inspection API binds the supplied source/map hash;
all identities remain visible, including quiet and negative movers. Incomplete
attempted details have their own list and are not relabelled as unexamined.
**These are plans, not execution or research priority. The current top-three
source workflow does not accept them.** There is no cursor service, automatic
next page, schedule, new capture or instruction for Human to execute129 pages.
The iterator verifies once then freezes code identities for bounded enumeration;
a single-page call still validates the supplied map before returning its slice.

## Publication and failure boundary

The existing Collector and original `_assemble`/blob reserve are reused. No new
Git source fetch, archive download, package dependency or producer is added.
Only the concept option enables this hook. Accepted company/source bytes and
serialized company-reading v1/v2 stay intact. A map-only failure rolls back only
its new/replacement files and adds an explicit map gap; it does not erase accepted
concept/institution/industry inputs or reset already-spent API counters. The
existing252-call/128MiB and bounded index limits win, including final README bytes.
If even the gap cannot fit the original publish boundary, publication fails
rather than silently relaxing a limit; the old read ref remains under the original
publisher's protection. No artifact code is executed.
