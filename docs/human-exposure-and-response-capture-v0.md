## 1. 用户入口应简单，记录责任留在系统侧

一次自然回应通常只需要 Human 说明：

> 我回应的是哪份研究／哪一点；我怎么看；这是研究意见还是已经明确作出的投资决定。

原对话已说清楚时，不再重复询问。理由和信心可不填写，缺失就保留缺失。不要要求 Human 手工抄哈希、研究版本、行情时间；记录者只从实际留存证据中整理这些信息。不能确认的字段写 UNKNOWN／未记录，不能生成看似精确的答案。

技术审批、“继续”“可以合并”不属于投资判断，也不会因使用这个模板变成预测。沉默、收到提醒、页面生成成功、attention_eligible=true，都不是同意或决定的证据。

## 2. 沿用既有记录，不创建第二套真相

已明确作出的投资决定，继续使用母协议的 Human Decision checkpoint，加入下方必要的暴露段即可；不要再生成一份复制相同语义的 Human Judgment。Action 仍独立记录，不从决定推断执行。

只有真实、明确、具有纵向价值且尚未被决定记录覆盖的研究回应，才保留一份薄的回应记录，引用被回应的材料。没有理由仅为增加样本量拆分旧记录。冻结后补充、更正或改变观点，创建后续记录并引用原记录，不改写原话。

System Research、Odds 和 Rehearsal 继续由现有对象拥有。缺少合格概率时，引用已冻结的研究／Decision Hygiene 文档，明确 Odds withheld；不为了让页面完整制造情景分布或数值赔率。commit 成功不等于观点为真。

## 3. Exposure 与 Response 分开

### Exposure：究竟知道哪份材料被呈现或看过

记录精确的材料版本、展示范围和能够证明的时间。区分：

- 实际系统呈现记录：只能证明呈现，不能证明阅读或理解。
- Human 同期明确自述：保留原话和其限定范围。
- Human 后来回忆：同时记录所述发生时间与现在的记录时间；不能升级为同期盲测证据。
- 没有可靠证据：UNKNOWN。未记录展示事件不等于没有暴露。

引用实际展示的版本，而不只是底层 ResearchSnapshot。相同 information_bundle_hash 可以有不同非权威 framing；Human 可能只看到摘要、某个情景或一段消息。记录可得的 surface / rehearsal hash、冻结 Git SHA+路径或原消息定位。不存在的 hash、系统日志或精确秒数不得补造。

“在看到这份系统结果之前已冻结的判断”只针对明确列出的材料范围成立。它不证明 Human 没有看过其他系统分析、公开研究或后来的事实，也不自动取得统计独立性。独立性要求发生顺序和信息范围的证据，不能由一个 INDEPENDENT 标签自己证明。

### Response：同意的是哪一层

分别写清回应对象是企业 thesis、证据／因果解释、估值、概率、研究流程，还是投资决定。可以同时同意 thesis、不同意价格，或认可研究但选择等待；不能强制压成一个看多／看空值。

“看过系统之后同意／反对／修改”是回应关系；“未暴露于某份材料”是信息条件，两者不混成互斥枚举。本补充中的词语是说明性语言，不是生产 schema、状态机或自动标签。

Human 原话与记录者摘要分栏。摘要仅用于导航，不能把“我认可研究”规范化成 BUY/HOLD，也不能把拒绝一个研究 frame 规范化成 bearish Belief。

## 4. 可直接使用的记录段

把必要部分附在新建的既有 checkpoint 中；回应未构成投资决定时只保留相应部分。下面是空白模板，不应自动填入任何实际案例。

```markdown
## Record identity
- 原案例／被回应问题：
- 本次实际表态时间、时区和时间精度：
- 本记录实际创建时间、记录者：
- 同期记录／后来自述／其他证据性质：
- 先前冻结记录的明确引用（没有则未记录）：

## Exposure（看过什么）
- 实际呈现材料的确切版本、路径+Git SHA／消息定位：
- 实际展示范围：摘要／全文／某段；未知则 UNKNOWN：
- 对应 Research / Odds / Rehearsal id/hash（仅在实际存在时）：
- 呈现时间及来源（不等同于已阅读）：
- Human 明确说明已看过的内容与时间（未说明则 UNKNOWN）：
- 此前是否已有冻结观点？其原文与定位：
- 任何“先于系统”的主张仅针对哪些精确材料？证据或限制：

## Response（回应什么）
- Human 原话：
- 回应的具体主张／范围：
- 同意、反对、修改或暂缓的内容（可多项，不强制方向标签）：
- Human 自述理由／不确定性（可选；未陈述不补写）：
- 记录者导航摘要，明确与原话分开：
- 是否明确作出投资决定？依据原话；不明确则尚未确立：
- 已有 Human Decision / Action checkpoint 引用（仅在存在时）：

## Clocks and evaluation（仅引用已经确立的内容）
- 研究信息 cutoff：
- 价格实际对应市场时点与口径：
- 查询／获取时间；报告生成时间（与市场时点分开）：
- 事先约定的评价问题、期限／事件及原始记录：
- 没有声明期限／未有合格 Odds／执行未知等限制：

## Boundaries
- 呈现 != 阅读；研究回应 != 投资决定；决定 != Action。
- 缺失暴露证据 != independent forecast。
- 不生成 Recommendation、执行指令或新的 canonical Human wake。
- System investment authority = NONE。
```

实际记录中的敏感执行或账户信息仅在确有授权且必要时保留；不从其他账户、券商持仓或相近时间交易猜测。这个补充不新建行为跟踪或隐蔽遥测。

## 5. Episode 与评价：只写必要的显式关联

如果将来比较 Quick / Deep / Human，不因三份记录就记成三次独立预测。使用明确的原案例／评价问题定位和方法版本关联；同 ticker 或相近日期不能自动证明同一个 episode，也不能把新证据驱动的后来判断强行并进旧实验。

文档数量、明确判断数量、episode 数量和统计独立样本数量不同。首次比较前冻结分组理由、信息集、评价问题和重叠期限处理；本补充不创建 Episode Kernel 对象、关系图服务或胜率面板。

市场结果、基本面观察、Human 评价和方法学习保持分离。触及一个价格只能回答预先定义的触价问题，不自动验证 thesis；期限到来但数据不可得，不自动“结算”。后来评价引用原记录和新证据，不能更改原目标或期限。

Future Observation 可成为新证据；Reflection Candidate 仍是待审阅建议；正式方法变更须有独立接受记录、时间和版本。原结果不会因为一个有利价格路径而自动获准作为下一轮方法经验。收益结果与好判断的归因继续使用母协议。

## 6. 首次使用的人工验收例，不冒充可执行测试

| 情境 | 应保留的结果 |
| --- | --- |
| “这个研究我认可，但没有决定买。” | 研究回应；无投资决定、无 Action；引用实际看到的版本。 |
| Human 先冻结观点，后看到某份 Quick 再修改 | 两条不被改写的记录及明确关联；只对该 Quick 的暴露先后作有范围的描述。 |
| 知道报告生成了，却没有阅读证据 | 呈现／阅读分别 UNKNOWN 或按实际证据记载；不能独立、不能同意。 |
| 三个月后回忆“当时我没看过” | 后来自述，保留记录时间；不填成当时系统日志或严格盲测。 |
| 同一底层 Research，用不同 framing 呈现 | 引用实际呈现版本；Research 哈希相同不代表暴露内容完全相同。 |
| Quick、Deep、Human 看后同意 | 各自保留真实记录；统计前有显式关联，不能默认三个独立 forecast。 |
| 周六生成报告，使用周五收盘价 | 价格节点周五；获取、生成和 Human 表态分别保留实际时点。 |
| 14 天内触价、期末反向且 thesis 未兑现 | 触价观察与期末结果分开，thesis 不自动确认；执行未知就不计算实际 PnL。 |

这些是模板走查标准，不计入 pytest 通过数量，不是新产生的前瞻样本。既有 CATL、Sanhua、Micron 等记录仅可被引用作后续只读界面的检查材料，不能补填以前没记录的 exposure、episode 或假想独立 Human forecast。

## 7. 完成标准与后续界面

第一项真实验收是自然出现的一次有增量信息的回应：能够从记录找回当时实际材料、已知暴露顺序和 Human 原话，并正确区分研究回应／决定／Action。若没有这样的新事件，保持“协议可用、真实验收待发生”，不人为催生一个判断。

接下来的只读 Timeline 应从这些既有冻结记录投影，第一屏只回答“当时怎么看、我回应什么、在等什么、后来如何”。证据、时钟与哈希可展开，不消失。不得成为第二套状态库，不重新打开已关闭研究，不新增第三条 canonical Human wake。

本补充没有自动采集、数据库、状态机、Kernel schema、产品部署或真实 Human 记录写入。所有现有公司状态、投资权限、Market/ledger 和 Sector 单日追加验收均不改变。
