Status: ENGINEERING PATH / NO LIVE PERMISSION REQUEST CREATED.
Reuse Decision: **THIN_ADAPTER**. #297 four-stage authority applies; Sub2API resource
authorization5646037620 is not a company-specific Human response.

This reuses the existing Human exposure/response operating protocol, the actual
GitHub Issue/comment as the canonical response, existing source refs, original
packet/candidate/Funnel validation, saved preparation, #337 execution and Retainer.
There is no new Human database, automatic intent classifier, approval service,
Research method, retry engine, scheduler or investment authority.

## Interaction, not the model, owns permission interpretation

When a genuine response naturally occurs, the interaction first reads the exact
shown R and result, retains the actual Human words in the existing delivery Issue
and reads that comment back. No company response is manufactured from an
engineering “continue”, a quota grant, a username, a model result or silence.

The interaction can then prepare the existing-style execution request at the fixed
`research_runs/disclosure-continuation-request.json` on reviewed main. This file is
an input to one named operation, not a second source of Human truth. It binds:

- the real Issue/comment ID, exact full recorded comment-body copy/hash and verbatim
  words; GitHub retention clocks are not invented Human message timestamps;
- the exact reading commit and the predecessor result actually included there;
- the predecessor packet and original input/candidate, or a real pre-execution
  failure without inventing an input/Funnel;
- the new original assessment key, previous question, focused follow-up question
  and why the new body could discriminate the same problem.

The schema is a local host-request format, not a new Kernel/Human entity. A source
body cannot name its own approval. Only a request at this fixed path on the current
trusted main can opt in; ordinary producer events never opt in by themselves.
The implementation does NOT create an enabled request or any synthetic permission
file in the live repository. Tests use explicitly synthetic in-memory comments.

Actual interpretation of genuine Human intent and “same economic question” belongs
to the interaction/review. The code validates exact binding, not the truth of that
interpretation. GitHub author identity is deliberately not a permission signal:
connector-generated comments can use the owner's username too.

## No renamed retry

The new packet must preserve the company and have a different original work key.
A changed time, old research context or wording alone is insufficient. At least
one original primary PDF must differ, or a previously NO_TEXT required body must
now have a qualified EXTRACTED representation that passes source preparation.
An already-readable same PDF does not become new Evidence merely because the
extractor now inserts different spaces. Old inputs, failures and markers remain.

Original FIFO/intake remain unchanged. In explicit continuation mode the target
must actually be in the named saved scan and not already attempted. Earlier legal
new FIFO questions can still be processed under the separate project resource
permission; they are not labeled Human continuations. Once the named target is
retained, the invocation stops. A failed or unavailable target cannot be replaced
by another company and called successful continuation.

## Actual checked path

The binder reads the reviewed request and original predecessor sources at exact
Git refs, invokes the ORIGINAL candidate/outcome validator, validates historical
exposure, and directly rereads the real Issue comment. The body/ID/repository and
retention clocks must still match; an edited/missing/wrong response fails closed.

Preparation adds the exact permission/request/predecessor/exposure references to
the original input. Only a minimized prior AI-result context, focused question and
new-body identities are added to the public model context. The actual Human
comment/body/username is not sent to the model. Prior AI output is labeled as a
candidate, not new primary Evidence or accepted Research.

Immediately before #337 execution the trusted host repeats the continuation
binding check and compares its public context to the frozen input. The unchanged
#337 path then enforces create-only launch, fresh original admission, original
Pre/necessary Quick, candidate/Funnel validation and retention. No second model
loop exists. A repeated request stops at the existing work reservation/launch.

The existing saved-disclosure workflow's manual `continue-research=true` opt-in
uses only this fixed main request and the exact named saved scan run. It does not
accept arbitrary permission text or a request path from a dispatch/source. Normal
scheduled-scan work does not auto-continue a Human case. Completion uses the same
fixed reading publication; candidate visibility still does not imply semantic
acceptance, registered DEEPEN, Belief/Odds update, investment decision or Action.
