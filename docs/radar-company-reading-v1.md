Previously the independent institutional source existed only in a 30-day Actions
attachment. The normal fixed reading could not join it to Sector leaders or show
existing company research context. A reader had to move separate lists between
chats. Reuse Decision: REUSE + THIN_COMPOSITION.

Reuse the existing Collector/archive/immutable read ref/publisher and unchanged
institutional capture verifier, exact raw-response reconstruction, Sector pool,
explicit purpose references and Stock business-work outcomes. The only new
composition is a company-first view and a bounded optional saved-source read.
No provider, queue, state registry, research engine, score or dependency is added.

native workflow_run listener; neither source receives a new clock/schedule.

## Source and time identity

The optional reader selects the newest main invocation of the exact institutional
workflow within a stated 20-run metadata window. It does not search older
successes after the latest attempt fails, remains active, expires or is rejected.
Full run metadata must agree with the selected identity; only successful fresh
manual main attempts can contribute a qualified source. Invalid sources remain
visible gaps. Independently available Sector observations still remain readable.

The original artifact archive is checked by `current_state.unpack_archive`.
`institutional_radar_capture.verify` runs on its exact eight payload files using
TRUSTED installed code, never the executable TAR inside the artifact. Its existing
implementation-hash compatibility check is retained. The origin workflow's small
CLI verification receipt contains only status/capture_hash; the new reader also
obtains a full local original-input replay result, not a fabricated origin receipt.
Run/capture clocks, source identity and LIVE provenance must agree.

The exact archive, payload and replay receipt are retained by the existing
read-model publisher into immutable Git history. This is read/evidence retention,
not production restore or a promise of eternal backup. An expired remote artifact
is not re-admitted merely because historical read copies remain. Daily acquisition
is still NOT enabled. New producer requests/model calls by this reader: zero.

## One security, distinct facts and questions

All retained leaders from every qualified Sector group and driver and every
institutional company contribute. Only exact normalized security codes join;
each origin retains its own date, source acquisition/generation clock, original
row/reference and institutional 1/3-day windows. Cross-source name differences
are visible, not silently resolved. No cross-window flow sum or common fake date
is created; this is neither atomic data nor historical first-vintage knowledge.

Saved Stock dispositions retain their own market date and lane health, including
an old readable copy beneath a newer input rejection. No matching disposition
means outside the supplied saved scope, NOT conditions-not-met.

Existing explicit-purpose Research references and exactly matched Stock first-
business outcomes are copied without supersession or acceptance. A method note is
not Full Research; a pre-execution failure is not WAIT; an absent record is not
never-researched. The scope excludes complete cross-repository research history.
Disclosure-work read status/gaps remain visible but free-text/six-digit identities
are not guessed into security matches. Root/child work keeps exact lineage.

Question text is derived orientation: business exposure/contradicting evidence,
overlapping institutional windows, and recovery of an existing failed baseline.
It is NOT Pre, Quick, a new admission or a reason why the stock moved. No company
is ranked as an investment or automatically sent to a model.

## Integration and bounds

`current_state_delivery_with_odds_watch.Collector.collect` calls the optional
reader only with the publisher CLI flag `--include-radar-discovery`,
after original baseline and Research collection. It preserves the existing
180+72 overall API envelope, 128MiB retained-byte bound, 192KiB index and original
publication reserve. It does not add a new budget. A preflight covers the bounded
metadata/archive reads and added blob writes. Optional failures roll back only
new optional files/cache, never API counters or original inputs. Finite stages
identify budget/run/archive/replay/retention failures without saving exception text.

The main index has a compact `research.radar_discovery` and links to
`details/radar/index.html` / `company-reading.json`. Exact pre-extension context
is saved as `base-context.json`; the view binds its reading_hash. Full company
rows stay out of the bounded main index. Relative links remain in the SAME pinned
reading commit. HTML has no scripts/remote assets, and source text is escaped.

The existing publisher listens to requested/completed institutional workflow
invocations; this only reads existing outputs and preserves active/failed state.
No auto-dispatch, rerun, source cadence, Research/Watch/Odds/Action is introduced.
